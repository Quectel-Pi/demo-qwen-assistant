# 非模型工程问题修复报告

## 范围和结论

根据用户“除了模型不准确的问题，其他问题请修复”的授权，修复本轮能复现的工程问题。
没有替换 LLM/Vision/ASR/TTS/VAD 模型，没有改 context、max-new、量化或模型解码参数。

结论：当前复现的语音队列/静音/冷启动、GTK线程、连接生命周期与音频设备争用问题已修复。
35项单元回归通过，最终16项真机工程回归通过；不能据此声称模型回答或语音识别完全正确。

## 修复内容

### 1. 首句朗读、队列丢句和界面卡顿

- 旧代码在共享语音引擎尚未加载时直接调用合成，异常被静默忽略，首句可能丢失。
- 合成线程现在在后台等待引擎就绪；初始化失败通过UI提示，不阻塞GTK。
- 输入文字队列不再达到8句就丢弃。PCM队列仍有界，背压只阻塞工作线程。
- finish() 改为非阻塞、幂等结束信号；结束后的迟到文字不会进入下一轮。
- 播放结束不再依赖可能被有界PCM队列丢掉的哨兵。
- 共享TTS调用和扬声器播放均串行化；快速切轮不会并发进入同一引擎。

真机：语音引擎仍加载时发问，最终首句正常播放；突发16句合成16句、播放16句；
finish约0.01ms。冷启动仍需等语音模型加载，不能把LLM的首字耗时当成出声耗时。

### 2. 静音、异常和线程安全

- 静音后不再从 _on_done 的旧兜底分支继续整段朗读。
- 请求失败时停止本轮播报、清除尾句缓冲，避免播旧内容。
- 重新开启朗读时，可以为正在生成的剩余文本开启新播报器。
- 麦克风识别中的半句话被取消后，不再作为新问题提交。
- 语音工作线程的状态更新和关闭麦克风按钮状态统一回GTK主线程。
- 音频错误明确反馈；底层aplay非零退出码不再被算成播放成功。
- 生成期间禁止清空；服务端清空失败时保留本地对话，防止前后端历史不一致。

真机：静音期间新增TTS调用为0；快速切轮TTS峰值并发为1；模拟播放错误有提示且未被标为已播放；
状态控件实际更新在线程主循环执行；取消麦克风录入不提交残句。

### 3. 连接生命周期

- close() 清空 busy、socket和buffered file，先shutdown唤醒读线程，再回收资源。
- 每条连接的接收线程持有自己的句柄和generation，不再读取替换连接的共享file。
- 已排到GTK队列中的旧连接回调也受generation保护，不能污染新连接。
- 收尾回调先完成旧气泡，再把控件恢复可输入。
- 独立控制请求按完整JSON行读取并校验ev；clear返回error不再被误判为成功。

真机：连续20次重连成功，最后只有1个接收线程；实际停止生成返回aborted=1，随后可继续问答。
未重启推理服务，服务PID仍为4603。

### 4. 音频采集路由与就绪时序

录音存在近满幅采样和ES8389同卡录放音争用。本次没有盲目固化增益：

- 先试模拟采集增益降低6dB；削波有所下降但转写未改善，因此全部恢复原值。
- 设备既有文档也说明ES8389同卡录放音共享时钟，不适合作为可靠全双工。
- 默认改为独立USB摄像头麦克风 `plughw:CARD=U1080P,DEV=0`，扬声器仍用原 `hw:0,0`。
- 使用ALSA稳定声卡名，不硬编码USB的card3序号。
- 用户显式 `MIC_DEVICE` 优先；没有USB麦克风时回退板载输入，并使用半双工互斥。
- 同卡回退时不做声控打断，仍可使用UI停止按钮；独立USB输入时保留声控打断路径。
- 采集开启后等实际PCM并短暂预热，随后才提示“在听”，不以创建arecord进程冒充可用。
- 采集在初始化/等待半双工锁时取消，也不会稍后重新开麦。

对照采样：共享声卡的近满幅比例约2.18%，USB采集为0%。USB预热对照的3条固定语句，
两条完整匹配，一条仍有2个字符错误（合计2/41）；这是小样本、现场环境下的观察，
不是通用ASR准确率承诺。无预热试验还出现过空转写，原始数据完整保留，未筛掉失败样本。

没有更改DTS/MCLK，没有改永久混音器增益。ADC/PGA增益保持试验前原值。
ASR自身错字、LLM数学/记忆/拒答/跑题问题仍然属于未修的模型质量范围。
